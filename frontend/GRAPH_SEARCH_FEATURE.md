# 图节点搜索功能

## ✅ 已实施

为 `OntologyDetailGraph` 组件添加了节点搜索功能。

---

## 🎯 功能特性

### 1. 模糊搜索
- **输入框**：工具栏左侧，240px 宽
- **匹配逻辑**：模糊匹配节点标签（不区分大小写）
- **实时反馈**：输入即搜索，无需点击按钮

### 2. 视觉高亮
- **当前结果**：蓝色高亮（`active` 状态）
- **其他匹配**：灰色高亮（`hover` 状态）
- **非匹配节点**：压暗显示（`dimmed` 状态，opacity: 0.2）

### 3. 结果导航
- **计数显示**：`1/5` 格式显示当前位置
- **上下按钮**：`↑` 上一个，`↓` 下一个
- **键盘快捷键**：回车键跳转到下一个结果
- **自动聚焦**：切换结果时自动将节点移到视口中心（300ms 动画）

### 4. 清空搜索
- **清空按钮**：输入框右侧的 × 图标
- **行为**：移除所有高亮，恢复所有节点到默认状态

## 🔧 技术实现

### 状态管理
```typescript
const [searchValue, setSearchValue] = useState("");           // 搜索关键词
const [searchResultIndex, setSearchResultIndex] = useState(0); // 当前结果索引
const [searchResults, setSearchResults] = useState<string[]>([]); // 匹配的节点 ID 列表
```

### 核心函数

#### `handleSearch(value: string)`
1. 清空搜索 → 恢复所有节点到 `default` 状态
2. 模糊匹配 → 遍历所有节点，匹配 `label` 字段
3. 高亮第一个结果 → 调用 `highlightSearchResult`

#### `highlightSearchResult(g, matches, index)`
1. 设置节点状态：
   - 当前结果 → `active`
   - 其他匹配 → `hover`
   - 非匹配 → `dimmed`
2. 调用 `g.focusElement()` 将节点移到中心

#### `handleNextResult()` / `handlePrevResult()`
- 循环切换结果索引
- 调用 `highlightSearchResult` 更新高亮

## 📝 使用场景

### 场景 1：快速定位对象
用户记得对象名称中的某个关键词（如"订单"），通过搜索快速定位到相关节点。

### 场景 2：验证对象存在性
用户想确认某个对象是否在当前视图中，通过搜索得到"0 结果"或"找到 N 个"。

### 场景 3：遍历同类对象
搜索"明细"，通过 ↑↓ 按钮依次查看所有包含"明细"的节点。

### 访问页面
```
http://localhost:5180/segments/{板块ID}

```

### 测试步骤
1. **基础搜索**：
   - 输入关键词（如"订单"）
   - 观察匹配节点被高亮，非匹配节点压暗
   - 确认计数显示正确（如"1/3"）

2. **结果导航**：
   - 点击 ↓ 按钮或按回车键
   - 观察当前高亮节点切换
   - 确认视口自动移动到新节点

3. **清空搜索**：
   - 点击输入框右侧的 × 图标
   - 确认所有节点恢复正常显示

4. **无结果场景**：
   - 输入不存在的关键词（如"xyz123"）
   - 确认无计数显示，所有节点恢复默认状态

5. **边界情况**：
   - 只有 1 个结果 → 计数显示"1/1"，↑↓ 按钮不切换
   - 空输入 → 清空所有高亮

## 📊 性能考虑

- **搜索复杂度**：O(n)，n 为节点数（通常 < 100）
- **状态更新**：批量调用 `setElementState`，一次性更新所有节点
- **动画性能**：`focusElement` 使用 300ms 动画，流畅且不卡顿
